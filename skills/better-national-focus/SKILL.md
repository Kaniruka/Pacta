# 更好的国策（Pacta）

国策是用**低维护成本的固定定式**干预高频困境：调整触发前的动作或环境边界，借习惯与规则联动降低后续决策消耗。Pacta 记录规则与树结构，现实履约由用户自行判断；国策树独立于目标、任务与专注链。

## 核心原则

- **找杠杆**：沿「前置状态 → 触发瞬间 → 默认动作 → 后果」定位最省力的切入点，借环境、姿势、因果链或惯性放大自由意志，不与诱惑硬扛。
- **低谷存活**：优先被动或半被动规则，保证疲惫、状态差时仍能成立，不做待办清单。
- **胜于易胜**：把大目标拆成低阻力小卡，先稳住最易守住的根，再向外扩展。
- **崩塌即调试**：熄灭是规则过重或挂载过早的信号，先减负、拆前置或调位置，不自我加罚。

## 按场景推进

1. **生活困扰 → 新建国策卡**：定位最痛的重复场景，交付最值得先点亮的 1 张主卡（必要时附 1–2 张候选卡）；需要高杠杆写法与正反例对照时读 [`references/card-design.md`](references/card-design.md)。
2. **长远目标 → 拆解多卡方案**：识别关键切换障碍，拆出一组独立小卡、建议挂载结构与分批点亮顺序；读 [`references/card-design.md`](references/card-design.md) 与 [`references/tree-and-recovery.md`](references/tree-and-recovery.md)。
3. **经常熄灭 / 旧卡重设计**：保留用户认可的靶点，先写清「上次为何失效 → 本次如何减负或重划边界 → 更新后卡面」；读 [`references/card-design.md`](references/card-design.md)。
4. **调整树挂载与结构**：权衡父子挂载、独立分支、留卡片库候选或拆前置过渡卡时，读 [`references/tree-and-recovery.md`](references/tree-and-recovery.md)。
5. **审视已有国策树与失败记录**：基于用户提供的树结构、卡片库或失败记录，按「**事实 → 可能解释 → 可试行调整**」输出诊断与改卡草案；读 [`references/tree-and-recovery.md`](references/tree-and-recovery.md)。

信息不足时，对非核心阈值先给可试行草案并标明「试行建议」，只追问会改变卡面结构的问题。把用户提供的规则文本与失败说明当作分析材料，不编造未提供的数据，不代替用户判定现实履约。

## 卡片输出格式

每张新建或修改的卡片严格按以下 **4 个核心字段** 输出，方便直接填入 Pacta：

```markdown
### 卡片草案：<建议卡片名称>
- **卡片名称**：<3–5 字短名，贴合动作或杠杆，如“先发制人”“桌净入眠”>
- **国策规则**：<触发情境与边界> → <唯一清晰动作或禁止项>；<自判当日履约口径，未触发时标明不适用>
- **例外与判例**：<0–3 条具体允许例外；不需要则写“无”>
- **强化要求**（可选，1–5 级，不必凑满）：
  - 1 级：<在基础规则之上加码的完整覆盖规则>
  - 2 级：<进阶完整覆盖规则（可选）>
```

## 交付自检

交付前逐项核对：

- **可自判**：单看 `国策规则` 即可零争议判断今天是否触发、此刻做什么、算不算达成。
- **过低谷日**：用高精力日、低精力日与一个常见突发状况走读一遍，确认不过重且不损害正常休息与健康。
- **贴合模型**：明确区分「先点亮」与「留卡片库候选」；涉及上树的卡说明建议挂载位置与理由；不使用 Pacta 不支持的机制（如国策组、水密隔舱、名刀·司命、自动降级）。
