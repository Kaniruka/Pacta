# 国策树结构、演进与失败复盘（Pacta 模型）

## 1. 国策树核心运转规则

- **两步上线**：新卡先建在**卡片库**（不参与每日结算），确认当前精力能承接后再挂入**国策树**（作为顶层根节点，或挂在某张稳定卡之下）并手动点亮。
- **每日检查点与三态**：每日在用户账号显示时区当地 **04:00** 结算。节点分三态：**点亮**（当前国策日已确认有效）、**待今日确认**（跨检查点后进入等待确认，视觉未点亮但尚未失败）、**真正熄灭**（超过检查点仍未确认，或用户主动熄灭）。
- **级联熄灭与内化保留**：任一节点失败会连带熄灭其所有后代并清空这些节点的当前连胜；**历史最高连胜**与累计成功天数（内化进度，累计满 `180` 个成功国策日标记为「已内化」）不会因熄灭清零。父节点未点亮时，子节点不能单独点亮。

## 2. 父子挂载与分支取舍（四选一）

规划或重构两张卡 A 与 B 的位置时，明确选择以下四种结构之一并说明原因：

1. **B 挂在 A 下方**：仅当 A 足够稳健（能“穿越牛熊”）、或是 B 的真实前置支撑时采用；一方面不易被 A 误伤，另一方面用连带代价反向保护 A。
2. **A 与 B 同作独立顶层分支**：分属不同生活时段或场景、互不构成前置依赖，保持独立以隔离单点失守的波及面。
3. **只先点亮更稳的那张，另一张留卡片库候选**：低谷期同时维护成本过高时，优先只让能直接改善状态的那张上树。
4. **拆前置过渡卡**：某张卡反复失守时，先在其前拆出一张阻力更低的过渡卡，稳住后再挂回目标卡。

审视现有国策树时重点排查：
- 顶层根节点是否放了高阻力或易受外界打断的脆弱卡；
- 是否存在缺乏实质依赖关系的过长单链（一处失误拖垮整条线）；
- 是否在同一时段堆叠了多张互相竞争精力的主动卡。

## 3. 崩塌即调试器与肉鸽式迭代

熄灭不是失败证明，而是最高效的调试器——它说明当前规则或挂载顺序在真实生活波动下还不够自然。按失效根因对症改造：

- **维护成本过高** → 拆成 2–3 张更小卡，或将强化等级手动切回低档／基础要求；
- **疲惫或低谷期失守** → 移出根部或退回卡片库，先在上游补作息、离屏、环境类低成本卡（农村包围城市）；
- **经常忘记执行** → 改挂到更强的日常物理锚点（进门、饭后、洗漱后），减少凭记忆启动；
- **现实条件变化** → 收窄触发情境或补充具体客观的 `例外与判例`。

**肉鸽式积累**：即便整条分支熄灭重来，各卡已积累的内化天数仍在。二次重走或换路挂载时，旧卡维护阻力会明显低于第一轮，无需因为连胜归零而推倒重来或陷入挫败。

## 4. 基于已有树与失败记录的复盘规范

当用户提供已有国策树、卡片库或失败记录（无论手动粘贴还是通过外部数据读取）请求诊断时，遵循以下分析口径：

- **三段输出**：严格分开 **事实 → 可能解释 → 可试行调整**。事实只陈述观察到的规则文本、树挂载关系、连胜／内化数值与失败记录；归因推断一律标为假设，并指出仍缺哪些现实背景；建议落成可直接修改的 4 字段卡面草案或调树方案。
- **精准识别对象**：数据带有稳定卡片 ID 或事件 ID 时按 ID 引用，不把同名卡混为一谈；历史记录中已移除或已删除的卡片仍保留为有效历史证据。
- **区分失败类型与波及关系**：
  - 区分**主动熄灭**与**未完成今日确认**（漏确认只说明未完成确认动作，不能直接推断当天现实未履约）；
  - 区分**独立失败源**与**连带熄灭的后代**（级联熄灭的后代不是额外的独立违约次数）；
  - 区分失败当时**冻结的树结构与当时规则**、**原始失败原因**以及**事后补充的复盘说明**；绝不用当前改过的规则倒推历史失败。
- **诚实说明数据边界**：累计成功天数与内化进度是熟悉度参考代理，不是逐日成功日历，也不等同于真实习惯形成测量；无记录或范围截断时明确说明，不凭空补全。

## 5. 与 RSIP 原文的机制划界（Pacta 不支持的机制）

RSIP 原文的部分扩展机制**刻意未引入 Pacta**，设计方案与复盘建议中不得虚构或假设 App 具备这些能力：

| 原文机制 | Pacta 现状 | 替代做法 |
| --- | --- | --- |
| **国策组（N 选 M 存活容错）** | 无组合容错节点 | 用独立顶层分支隔离风险，脆弱卡放叶节点 |
| **水密隔舱（全局冻结结算）** | 无冻结／暂停日机制 | 优先半被动触发（未触发不违约）；遇重病、出差等大波动坦然接受熄灭并记录复盘说明，恢复后借既有内化进度快速重建 |
| **名刀·司命（替换熄灭节点保子节点）** | 熄灭严格级联，不支持无损替换 | 根部只放最稳的卡，避免把高波动卡放在子节点上方 |
| **每日限加 1 张硬上限** | 客户端不锁死每日新增数 | 方法论上仍建议稳住再加，一次不超过 1–2 张 |
| **强化自动降级保护／储备释放** | 强化档位仅手动切换，不自动挡灾 | 低谷期察觉吃力时主动切回低档或基础要求 |
| **CTDP 专注链规则** | Pacta 有独立的「专注链」与「计划／任务」模块 | 定时专注、待办任务留在专注链与计划中，国策只守住高频行为的触发边界 |
