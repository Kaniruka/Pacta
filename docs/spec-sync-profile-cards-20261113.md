# Pacta 同步、个人页面与国策卡改进规格

状态：2026-11-13 用户确认全部五项拆分、依赖关系和测试范围，并授权发布GitHub及完整实施。内化公式已单独实施并保留；其余进入实施。

## Problem Statement

同步弹层暴露设备技术字段和大段说明，用户难以快速选择上传或下载。云端只有最新快照，无法找回历史备份；今日确认后还需要手动上传。个人页面缺少可编辑身份和简洁的个人记录摘要，权限入口较隐蔽。国策节点弹层混合阅读与编辑信息，强化要求管理过于繁重。

## Solution

同步采用简洁入口、按操作展示的覆盖确认、最近15份云备份和可选的今日确认后自动上传。个人页提供头像昵称、两组统计、记录入口和集中提醒设置；新增每日打开 Pacta 的本机提醒，按使用场景申请权限。国策卡采用已确认的“轻量分层”原型，保持领域行为不变。

### 展示与行为

- 来源只显示 Android 型号或 Windows 设备名及平台，不显示设备 ID 和独立厂商字段；无法取得时显示对应平台的未知来源，不伪造名称。
- 同步首页显示本机上次成功同步状态；操作层提供上传、下载、自动上传开关和历史备份入口。仅检查、失败、取消不更新成功时间。
- 覆盖确认保留必要的数据时间及后果。正常页面不展开技术诊断。
- 云端保存最近15份成功写入的备份，包含最新份；成功写入新版本后才淘汰最旧版本。迁移保留现存快照，旧客户端不能绕过备份保留和并发保护。
- 历史列表显示时间、来源、记录数。恢复选中版本到本机前持久保存本机恢复点；保存失败则不替换。本机恢复点按用户隔离，提供可找回入口，与云端15份分开，避免恢复准备动作先覆盖当前云端。恢复后不得自动上传历史结果。
- 自动上传开关默认关闭，作为本机当前用户偏好保存；开启后单个或批量今日确认成功才产生上传请求，整批只执行一次。普通业务编辑不单独触发上传。
- 离线待上传请求跨重启保留，恢复联网且用户仍启用、登录与可访问条件仍成立时重试；合并请求上传届时最新本机快照，不上传陈旧的排队副本。关闭开关、切换账号或恢复备份后不得继续执行旧请求。
- 遇到未处理的云版本，不自动覆盖；忽略提醒不等于授权覆盖。云端修订与本地指纹检查继续有效，首次遇到既有云快照也需要用户处理。重试不得重复生成相同上传请求的历史版本。
- 头像昵称作为账号资料单独维护，业务备份恢复不回滚个人资料；本地缓存支持离线查看，资料写入失败明确显示且可重试。头像优先使用系统图片选择器，不为选单张图片索取整个媒体库访问。
- 选图后进入固定圆形预览的头像裁剪页，可拖动位置、双指或滑杆缩放、重置；确认只更新编辑草稿，资料页保存才写入并同步。取消选择／裁剪保持旧头像，可重新裁剪已有头像或本次原图。来源限 PNG／JPEG、5 MB，保存为最长边不超过384像素且不超过256 KB的方形PNG；预览与输出使用同一裁剪区域，圆形仅用于显示。
- 名片采用两组紧凑统计；当前点亮数仅统计树中 Lit 状态的未删除卡片，不将 Pending Today Confirmation 当成已确认。专注完成次数仅计算已接受的 completed 记录；累计有效时间沿用现有可计入的结算记录口径，包含符合现行规则的失败记录有效时间，不计暂停或排除区间。
- 国策第二项统计保留“已内化数量”，按本用户未删除卡片累计成功国策日 `S >= 180` 计数。用户最终接受公式 `I = min(100, 100 * (1 - exp(-S / 60)) / (1 - exp(-3)))`，180天达到100%并封顶；四舍五入显示不用于判定。替代此前“严格超过100%”及待定增长公式建议，不改写历史成功日。
- 提醒入口集中专注／预约通知、国策待确认提醒和新增的每日打开 Pacta 提醒。每日提醒有独立开关与可修改时间，默认关闭，首次开启选择时间；按本机当地时间每天一次，点击进入应用看板，与是否存在待确认节点无关。不补发多日积压提醒。
- 通知、日历等权限在用户启用相应能力时申请，拒绝不阻塞核心功能；系统不再允许请求时提供设置入口。普通通知权限与精确闹钟特殊授权分别处理。提醒和权限属于设备设置，不随业务快照替换或跨设备复制。
- Android 与 Windows 均需提供真实平台证据；Windows 是否可在完全退出后提醒须核实原生实现，不以 Android 调度能力推断，并在界面说明实际限制。
- 国策节点弹层保留标题、当前规则和状态操作／结构操作，去掉分割横线、例外与判例及强化入口。详情页展示可展开例外与判例、记录、编辑入口。编辑卡片包含强化管理入口；管理页突出当前要求，其他等级紧凑展示，编辑时折叠提供基础规则对照。
- 2026-11-14 UI 修订：待今日确认节点的“确认／熄灭”为同排等宽按钮；已点亮只留“熄灭”，已熄灭只留“点亮”，原操作守卫不变。同类折叠区使用共享样式，标题与同级内容字号一致，展开无上下装饰横线；输入框边框及浮动标签完整可见。编辑例外的分组标题不在框内重复，收起时释放该区域输入焦点，重开保留草稿。
- 强化上限五级（不含基础），手动切换、版本留存、即时生效和不重置记录规则保持不变。编辑未保存内容与进入强化管理后的返回路径需一致，不能静默丢失表单。

## User Stories

1. As a 用户, I want 同步入口只显示必要状态, so that 快速判断是否需要操作。
2. As a 用户, I want 来源显示型号或设备名及平台, so that 识别数据来自哪里。
3. As a 用户, I want 不看到设备ID等技术细节, so that 页面保持简洁。
4. As a 用户, I want 上传前明确覆盖后果, so that 不误丢云端独有记录。
5. As a 用户, I want 下载前明确覆盖后果, so that 不误丢本机独有记录。
6. As a 用户, I want 查看最近15份云备份, so that 找回先前数据。
7. As a 用户, I want 备份有时间、来源和数量, so that 能辨认版本。
8. As a 用户, I want 恢复前保留本机恢复点, so that 恢复选错时可找回。
9. As a 用户, I want 恢复失败保持原数据, so that 不产生半份数据。
10. As a 用户, I want 恢复旧版本不自动覆盖云端, so that 可以先核对。
11. As a 用户, I want 自主开启今日确认后自动上传, so that 减少重复操作。
12. As a 用户, I want 批量确认只上传一次, so that 避免重复备份。
13. As a 离线用户, I want 确认成功且稍后重试上传, so that 网络不影响使用。
14. As a 多设备用户, I want 云版本冲突停止自动覆盖, so that 不意外丢掉另一设备记录。
15. As a 用户, I want 关闭自动上传后停止排队任务, so that 开关如实控制传输。
16. As a 用户, I want 切换账号后不会传输上一账号数据, so that 保持隔离。
17. As a 用户, I want 编辑头像和昵称, so that 拥有可识别的个人资料。
18. As a 多设备用户, I want 个人资料随账号一致, so that 不重复设置。
19. As a 用户, I want 名片有四项清楚的统计, so that 看到当前状态与长期投入。
20. As a 用户, I want 由统计进入详细记录, so that 能理解数据来源。
21. As a 用户, I want 集中管理提醒, so that 不在设置中反复查找。
22. As a 用户, I want 每日定时提醒打开Pacta, so that 建立使用习惯。
23. As a 用户, I want 改时间或关闭后不收到旧提醒, so that 提醒遵从当前选择。
24. As a 用户, I want 在需要时才看到权限申请, so that 理解其用途。
25. As a 用户, I want 拒绝权限仍能使用核心功能, so that 保留控制权。
26. As a 用户, I want 节点弹层只呈现当前规则和操作, so that 能快速确认或调整节点。
27. As a 用户, I want 在详情按需展开例外与判例, so that 阅读层次清楚。
28. As a 用户, I want 从编辑卡片管理强化要求, so that 编辑操作集中。
29. As a 用户, I want 管理页突出当前要求, so that 明白正在执行哪条规则。
30. As a 用户, I want 编辑强化时按需查看基础规则, so that 避免重复信息占满页面。
31. As a 用户, I want 布局改造保留历史与五级规则, so that 记录不因外观调整变化。
32. As a Android或Windows用户, I want 亮暗主题和窄宽窗口均可操作, so that 两端使用一致。

## Implementation Decisions

- 复用快照仓储、云版本检查协调器、同步结果存储及App组合入口，增加历史列表／指定版本获取／恢复点和持久自动上传协调职责，不恢复逐实体合并。
- 备份创建、并发条件校验与保留上限在可信服务端原子执行，列表和内容读取遵守用户RLS和生命周期限制；账号清除包含历史备份和资料资产。
- 资料存储和头像资源独立于业务快照，使用认证身份隔离；客户端不携带管理员密钥。
- 复用已有领域统计、成功日和结算结果；新增已内化产品分类，但不代表现实习惯形成测量。新公式取代旧公式，既有记录按新公式显示，不改写成功日记录。
- 复用提醒服务、设备偏好和平台通道；新增每日提醒不能覆盖专注或国策通知标识，调度重入保持幂等。
- 卡片界面按已确认原型结构落地Flutter组件，保留现有主题、MiSans和状态规则。原型是假数据交互，不能用其简化逻辑替代领域验证。
- 精确补充ADR 0005的自动上传和历史保留契约；只替代对应条款，其余用户隔离、版本检查、事务恢复继续有效。

## Testing Decisions

以下测试边界已由用户确认；实现阶段按真实结果记录，不预先声明通过。

- 主边界是用户操作真实页面／AppShell、真实本地仓储和Drift，替换外部认证、云remote、系统权限及可控时钟。检验可见结果和持久状态，不断言私有控件树或内部调用顺序。
- 沿用现有同步App测试、快照仓储测试、国策编辑与强化测试、提醒计划／服务／设置页测试。覆盖空内容、失败重试、离线恢复、重复请求、账号切换、云冲突、备份淘汰、旧格式兼容及恢复失败不部分替换。
- 真实隔离Supabase项目验证迁移、历史保留、并发、跨用户RLS、头像资料及清除边界；不在真实用户数据上演练破坏性恢复。
- Android／Windows运行受影响页面，验证亮暗、窄宽布局、触摸／鼠标、权限拒绝与允许、提醒到达与点击返回、重启后状态。截图和日志保存同源证据。平台不具备的能力如实记录。
- Dart文件先format，再analyze及相关test；跨模块合入后完整test。代码评审分Standards／Spec，另做设计评审。

## Out of Scope

逐记录自动合并、自动下载、社交点赞／导入统计、邮箱提醒、无关设备权限、自动强化升级。无障碍、大字号和专项键盘范围沿用ADR 0007／0008。
