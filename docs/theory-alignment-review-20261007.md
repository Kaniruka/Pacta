# CTDP / RSIP 与 Pacta 核对 — 2026-10-07

## 结论与评估边界

Pacta 已接住两套方法的主要结构：专注承诺与延迟启动、独立链记录、共享下必为例、国策触发条件与行动、树形回溯、失败后保留历史和累计进度。最明显的不足不是约束力不够，而是低负担尝试、意外容错和换路径指导没有同样完整地进入产品。

用户本次明确：app 应宽松、辅助用户，不起强约束作用。这个定位与 product-design.md 的 User agency 原则一致。本文将“理论差异”“现行范围取舍”“体验风险”分开，不把原文规则直接升级为需求，也不把有意简化报告成实现 bug。

依据为 [原 PDF](references/如何提升自制力.pdf)、GLOSSARY.md、product-design.md、核心规格、验收矩阵、requirements-decisions 和 ADR 0001–0005；抽查了专注仓库、国策仓库、模型和界面。页码均为 PDF 页序。本次为文档与静态代码核对，没有运行 app 或平台验收，也未对作者理论的科学有效性做外部验证。

## 术语需要说清什么

1. **Task / Focus Node**：文章的“任务链、任务节点”有时指一次专注单位；app 的 Task 是目标下的实际待办，Focus Node 是一次完成专注留下的节点。现行区分是正确适配，不应把完成倒计时说成任务已经完成。
2. **国策树父子关系**：除了视觉分组，现行关系还携带失败连带，不能让用户以为只是文件夹分类。文章的树主要服务加入顺序和路径搜索，并非证明某行为在现实中必然导致另一个行为。可在选父节点时解释连带效果，允许用户自由组织。
3. **下必为例**：app 是用户可维护的持续许可；原文强调同类情况在该链生命周期中始终允许。共享跨两条链、允许编辑删除、排除预约都是产品适配。不能宣称完整保留原文的永久判例机制，也不应为了“忠实”禁止用户修正规则。
4. **强化等级**：应理解为具体要求版本，而非奖励分数、真实能力等级或自动升级。现行手动选择、可回到基础要求、保留历史版本是合理的宽松适配。未达强化要求时是否仍满足基础要求，需要用户判断；不能简单等同基础规则失守。
5. **内化进度**：本次已在 CONTEXT 明确其为展示代理值，非真实习惯形成测量，并新增 CTDP / RSIP 来源概念。未改变累计公式、结算方式或界面文案。

## 用具体场景检查边界

- 用户生病三天，没有回家进门这个触发动作，也没有打开 app。原规则未必被违反，但当前漏确认会造成失败；这是 app 维护行为与现实规则之间最明显的缝隙。
- 用户想“先读两分钟试试”，选择普通链5分钟后退出。当前这是一次普通失败，会损害已有记录，不能称为无损侦查。
- 用户创建父卡“休息好”只是为了分类，把“饭后洗碗”挂在下面。父卡漏确认会连带孩子，因此挂载关系需要清楚说明后果。
- 用户连续成功日很多但仍依靠外部提醒。app 的内化百分比仍会上升，说明它只能代表记录积累，不能证明低维护成本或实际习惯已经形成。
- 用户移入卡片库去休假。这个动作并不冻结已有维护周期，还会拆散树关系；休整功能应有自己的明确语义。
- 用户未做到强化的10页，但完成基础的5页。现行可以主动切回基础要求；不能自动替用户判定当天成功，也不能用后来的版本改写先前要求。

## 建议优先级与现行边界

**优先澄清**：内化指标解释、侦查与普通短会话区别、父子失败连带说明。它们能先减少误解，不需要引入监督。

**下一轮产品决策优先**：无损侦查；漏登记与真实违约分开；用户主动休整；退出原因稍后补。这些是本次建议，并非已获批准的新功能，也未发布为 GitHub 实施任务。

**之后按需要考虑**：国策组、结构保留的路径重建、储君继承、主动阅读的国策示例与复盘。无需强制复刻一日一卡、固定精锐时长、自动监测手机或现实动作。app 已保留历史最大记录、失败后的实际投入时间、累计成功日和手动控制，这是应继续保留的辅助性设计。

当前行为与 ADR 0004 的 countdown / exception 边界没有新发现的实现冲突；若改变退出结果与例外路径，应连同该 ADR、规格和验收一起核对。ADR 0005 已取代逐记录云端合并/核对；历史文档和 product-design 末尾仍有旧核对描述，不应因此认定当前缺少自动同步或自愿历史改判。本文不新增 ADR，因为尚未选择新的、难逆转的业务方案。
