# T07: 云端来源设备型号与旧元数据兼容

状态：已发布 [T07 / #70](https://github.com/Kaniruka/Pacta/issues/70)，标签 ready-for-agent；原生父子和阻塞关系已核验。待实施、未验收。

## Parent

https://github.com/Kaniruka/Pacta/issues/63

## What to build

上传并展示实际可用的设备名和型号，使用户能识别来源设备，旧数据未知信息明确标注。

## Acceptance criteria

- [ ] Android读取品牌/型号、Windows读取厂商/机型并保留可辨识设备名，不采集序列号。
- [ ] 元数据贯通上传、云存储/读取及同步预览展示；获取失败/空值显示型号未知，原设备名保留，不能伪造旧型号或上传时间。
- [ ] 旧快照与旧版云表仍可查看/选择，缺新增元数据不导致失败；新增信息不得削弱RLS、当前用户校验或过期预览保护。
- [ ] Android15/Windows11真实运行读取并记录可用/未知回退，合成设备名测试不代替原生取证；隔离Supabase两端上传下载并显示对方来源。

## Blocked by

None (can start immediately)

## Validation notes

复用云remote边界注入型号获取失败并验证展示，真实平台读取和实际服务元数据往返另取证。无需等待卡片换弹层，可先在现有同步预览中演示。

仅陈述目标与验证要求；本轮未运行任何实现测试或设备验证。实施时按项目要求format、analyze及相关test，跨模块变更跑完整test；保留用户数据，真实服务使用隔离项目。
