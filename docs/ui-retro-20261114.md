# #91 UI 漏检复盘（2026-11-14）

依据：本轮用户截图与反馈、[原型 A](prototypes/pacta-card-prototype-20261113.html)、[原实施记录](issue-91-implementation.md)、[UI 指南](agents/ui.md)、`integration_test/national_focus_card_layers_device_test.dart`。本记录说明验收与环境缺口；修复后的平台结论由本轮实际设备证据记录承担。

## 按严重度排序

1. **高：实现偏离原型，上一轮评审漏检。** 用户指出待今日确认（`pendingTodayConfirmation`）时确认/熄灭仍纵向堆为 ListTile，折叠标题字号不一致、展开默认上下边框，以及编辑例外框浮动标签被裁切。原型 A 的 `.actions` 明确 `display:flex`、按钮 `flex:1`，确认今日与熄灭同组同排；`details summary` 无上下边框。实现没有完整转译这些层级。已有指南本来要求语义字号、真实运行与打开判读，并无文档要求纵排或保留双横线。不能把这些问题归因于提示词要求。

   状态覆盖也漏了分支：原 fixture 的 `05-card-editor` 在展开例外前截图；节点使用 lit 种子，没有待今日确认状态的双按钮排列截图。原实施记录包含详情展开、待核对行为测试及窄屏无异常测试，但“待核对”（`hasPendingReview`）会阻断动作，不能覆盖“待今日确认”的双按钮排列。记录末尾的“设计评审与 Standards/Spec 代码评审尚未进行”仅描述当时进度；此后本次对话主 Agent 已宣称复核通过，仍漏掉这些问题。原因是最终复核未逐状态捕获问题，不能据早期记录推断最终没有评审。只验证默认 widget 无异常不能判定视觉合格，先前通过表述超出了证据。现在验收入口要求按真实分支列状态、记录已判读/缺口，并明确存在性、无 overflow、截图成功不能替代视觉判断。

2. **中：同类控件散落，默认样式反复进入业务页面。** 原实现直接使用 `ExpansionTile`；其默认标题样式、展开边框与裁切行为需要在项目上下文内评估。修复集中到 `lib/src/ui/pacta_disclosure_section.dart`；新增 `test/ui/disclosure_usage_test.dart` 用 Dart AST 限制生产源码中此控件的构造入口。测试也验证注释与字符串不误报，普通、const 与带前缀构造可检出。它能阻止直接构造绕过共用组件，不能判定任意别名、工厂包装或最终像素效果；组件仍需 widget 与平台展开状态验收。

3. **中：已有检查没有自动执行入口。** 复盘时 `analysis_options.yaml` 已启用 flutter_lints，但仓库没有 `.github` 工作流，`.git/hooks` 只有 sample；不是缺少 lint 配置，而是分析与测试没有接入 CI。新增 Windows GitHub Actions，在 push/PR/手动触发时固定 Flutter 3.47.2，运行官方 MiSans 下载/哈希验证脚本、依赖解析、`flutter analyze`、全量 `flutter test`。Windows 与现有 native SQLite 本地测试证据一致；权限仅 `contents: read`，不传真实云凭据。

## 改进边界

没有向根 AGENTS.md 添加重复规则：它已路由到 UI 指南。机械模式由测试和 CI 执行，需判断的视觉状态留在 UI 验收。新工作流尚未在 GitHub runner 执行，不能报告远端 CI 已通过；字体源网络或 SDK 安装失败也应作为真实 CI 失败暴露。单元检查不能替代 Android/Windows 的实际截图判读。
