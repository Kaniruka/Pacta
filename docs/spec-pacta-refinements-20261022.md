# Pacta 看板、专注导航、视图偏好与云更新提示改进

> 范围更新（2026-10-23）：无障碍支持已长期退出产品范围，后续实现、评审和发布验收按 [ADR 0007](adr/0007-accessibility-out-of-product-scope.md) 执行；保留普通可读性、响应式、鼠标/触摸及 Windows 常规键盘要求。本文既有验收结果仅代表记录当时，未重新执行。

状态：Q1–Q15、最终摘要、测试边界及9票拆分/依赖均已确认；已发布为[Spec #63](https://github.com/Kaniruka/Pacta/issues/63)。[#64](https://github.com/Kaniruka/Pacta/issues/64)已实现、验收并关闭，代码`fece2f9`已推送；其余8票待实施，父Spec仍打开。实际证据见[#64验收记录](issue-64-validation.md)，分票状态见[索引](tickets-pacta-refinements-20261022/README.md)。

## Problem Statement

用户在看板无法为目标和任务补充简短背景，折叠目标仍留下添加入口，标题不能直接切换折叠。普通/精锐标签易被理解为难度等级。专注链主页面被不断增长的任务列表撑长；国策树的视图选择无法跨页面状态重建保留。云同步入口缺少简洁、持久的状态摘要，用户进入 App 时不知道其他设备是否上传了尚未处理的数据，来源设备也没有型号信息。

需求整理时的实现基线（早于#64）：目标/任务模型和存储均无描述字段；目标内部“添加任务”不受折叠条件控制；专注任务列表平铺主页面；国策视图切换仅更新页面内存；现有手动云同步为明确整份覆盖，点击后才检查云端并弹出对话框，未实现启动检查。国策偏好问题仅完成静态定位，未进行本轮设备冷启动复现。以下为整组目标行为；仅#64范围已有实施与验收证据，其余范围仍待完成。

## Solution

提供可选单行描述展示和标题区域折叠；隐藏折叠目标内部的任务与添加入口；保留分类领域规则、简化其看板呈现。采用用户认可原型中的专注主页→二级任务列表→设置→执行与恢复路径。本机按用户保存国策树视图偏好。简化云同步卡片，在明确授权前只读检查云版本，以“忽略”管理提醒；整份上传/下载继续由用户明确确认，设备来源补充型号。

## User Stories

1. As a 用户, I want 为目标填写可选描述, so that 我能补充目标背景而不拉长名称。
2. As a 用户, I want 为任务填写可选描述, so that 我能记录执行提示。
3. As a 用户, I want 在创建和编辑中修改或清空描述, so that 信息可随工作调整。
4. As a 用户, I want 空描述不占展示行, so that 看板保持紧凑。
5. As a 用户, I want 描述最多200个用户可见字符并将换行转为空格, so that 内容保持简短单段。
6. As a 用户, I want 看板描述一行省略且编辑可读全文, so that 长内容不撑高卡片且仍可查看。
7. As a 用户, I want 描述随重启和明确云快照传输保留, so that 内容不会丢失。
8. As a 旧数据用户, I want 缺描述字段的数据按空描述读取, so that 升级和下载仍可用。
9. As a 用户, I want 点击目标名称所在标题区域切换折叠, so that 无需寻找独立小按钮。
10. As a 用户, I want 箭头明确显示展开状态, so that 能预测点击结果。
11. As a 用户, I want 编辑或删除目标不触发折叠, so that 相邻操作互不干扰。
12. As a 键盘用户, I want 用Tab定位并用Enter或空格切换目标展开状态, so that 无鼠标也能操作。
13. 原读屏用户故事自 2026-10-23 起由 ADR 0007 取消，不再作为验收项；保留编号用于历史追溯。
14. As a 用户, I want 折叠目标隐藏任务、内部全部添加入口和空态说明, so that 收起后卡片真正紧凑。
15. As a 用户, I want 折叠后保留目标描述、任务数量、完成状态和编辑删除, so that 仍能识别目标。
16. As a 用户, I want 空目标也能折叠且重新展开恢复添加入口, so that 交互一致。
17. As a 用户, I want 各目标独立折叠并首次展开, so that 一个目标不会影响另一个。
18. As a 用户, I want 看板不常驻普通/精锐标签, so that 不把组织分类误解为难度判定。
19. As a 用户, I want 目标编辑称新任务默认分类、任务编辑称适用专注链, so that 两者用途明确。
20. As a 用户, I want 保留普通/精锐/两者分类及两条链的独立记录, so that 简化展示不改变领域行为。
21. As a 用户, I want 专注主页保留恢复、可选任务数量、任务入口、链摘要及历史而无任务预览列表, so that 任务再多主页也不无限增长。
22. As a 用户, I want 在二级任务列表浏览未删除且未完成任务, so that 选择行为集中明确。
23. As a 用户, I want 使用全部/精锐/普通筛选且两者任务进入两个模式列表, so that 可按当前需要选择任务。
24. As a 用户, I want 任务选择条目显示目标、分类、预计时长和专注进度, so that 开始前有足够上下文。
25. As a 用户, I want 未设置的预计时长如实显示, so that 不被虚构数值误导。
26. As a 用户, I want 选择任务后进入时长和本次模式设置, so that 能调整本次安排。
27. As a 用户, I want 取消设置返回列表且保留筛选与滚动位置, so that 不丢浏览上下文。
28. As a 用户, I want 开始后进入预约或专注执行页, so that 启动路径连贯。
29. As a 用户, I want 离开执行页返回专注主页且流程继续, so that 浏览应用不等于结束流程。
30. As a 用户, I want 已有预约、专注或暂停时优先恢复它, so that 不会意外创建第二个流程。
31. As a 用户, I want 原任务后来完成或删除后仍能恢复已有流程, so that 数据编辑不破坏承诺。
32. As a 用户, I want 最后一次成功开始预约或直接专注的模式成为下次默认, so that 两种启动路径一致。
33. As a 用户, I want 仅修改或取消设置不改变下次默认模式, so that 试选不会产生持久副作用。
34. As a 用户, I want 全部入口沿用上次模式、首次普通、模式筛选预选对应模式且仍可切换, so that 默认可预测。
35. As a 用户, I want 简洁/详细视图切换后立即保存并在真正重启后恢复, so that 不必反复选择。
36. As a 用户, I want 国策视图按本机当前用户隔离且不随云下载覆盖, so that 不同设备和用户各有偏好。
37. As a 用户, I want 首次使用默认简洁、偏好读取失败有回退和重试, so that 存储问题不阻断页面。
38. As a 用户, I want 云同步常驻卡片保持简洁且点击进入操作弹层, so that 低频复杂操作不占主界面。
39. As a Android用户, I want 底部弹窗提供同步操作, so that 触摸访问方便。
40. As a Windows用户, I want 居中限宽对话框提供相同操作并支持键盘退出, so that 桌面使用顺畅。
41. As a 用户, I want 正常状态右侧仅显示本机上次成功同步时间, so that 不把云端上传时间误当成本机同步时间。
42. As a 用户, I want 无同步记录显示尚未同步且工作/失败/待处理状态优先, so that 当前状态清楚。
43. As a 用户, I want 仅检查不刷新成功同步时间, so that 摘要真实。
44. As a 用户, I want 登录及可访问状态确认后冷启动检查云更新, so that 能发现其他设备数据。
45. As a 用户, I want 返回前台按5分钟节流检查, so that 及时发现变化又避免频繁请求。
46. As a 用户, I want 离线和检查失败不阻断使用也不弹错误对话框, so that 本地工作能继续。
47. As a 用户, I want 用未处理云版本而非设备时间判断更新, so that 时钟偏差不会导致漏报。
48. As a 用户, I want 首次发现已有云快照时提示且自己上传/已下载版本不再提示, so that 提醒与实际处理状态一致。
49. As a 用户, I want 点击忽略后同一版本跨重启不再主动提醒但仍可手动处理, so that 我能决定同步时机。
50. As a 用户, I want 关闭、返回或Escape仅关闭本次提示, so that 不会误标为忽略。
51. As a 用户, I want 新云版本可以再次提醒, so that 忽略旧版不会屏蔽后续更新。
52. As a 用户, I want 忽略与处理标记按本机用户保存且不被快照下载覆盖, so that 提醒状态稳定隔离。
53. As a 用户, I want 预约/专注/暂停期间仅见非阻断更新提示且选择提示延迟到流程结束, so that 专注不被自动弹层打断。
54. As a 用户, I want 未结束流程期间仍能主动查看/上传而不能下载, so that 保留控制权又不破坏当前流程。
55. As a 用户, I want 检查、忽略、取消均不改变本地业务数据, so that 只有明确授权才发生替换。
56. As a 用户, I want 上传/下载明确说明整份覆盖和独有记录丢弃且不默认方向, so that 理解取舍。
57. As a 用户, I want 本地有未同步修改时获得明确警告, so that 不误丢本地工作。
58. As a 用户, I want 预览后云端或本地变化要求重查且失败保留原数据, so that 不覆盖未看过的新变化。
59. As a 用户, I want 看见来源设备名与可用型号, so that 能识别快照来自哪台设备。
60. As a 旧数据用户, I want 未记录的设备型号和上传时间明确未知, so that 不被伪造元数据误导。
61. As a 旧数据用户, I want 旧版云数据也能稳定识别变化和被忽略, so that 不会重复提示同一份数据。

## Implementation Decisions

- 领域依据为 GLOSSARY、ADR 0003/0004/0005 及2026-10-22已接受补充。目标描述与任务描述是可选业务字段，空描述不占展示行；首尾去空白，粘贴换行为空格，按用户可见字符限制200，编辑支持全文读取。字段需贯通创建、编辑、存储和手动快照；旧数据缺字段兼容为空，不另造独立备注系统。
- 目标标题区域是可聚焦展开控制，箭头仅提供状态而非第二焦点；编辑/删除是独立操作。空目标和非空目标均隐藏全部内部添加入口和任务内容，保留目标自身摘要。首次展开，不新增跨启动折叠偏好。
- 分类规则保持不变，目标分类只建议新任务默认值；任务分类与本次模式不同，不迁移历史、不改变进行中归属。移除看板常驻分类标签，编辑采用已确认用语。
- 专注主页高度不随任务数增长；独立任务选择页面提供三个筛选和完整上下文。筛选与滚动在取消设置后恢复；已有流程恢复优先。计时、失败结算、暂停依据、预约15分钟自动交接等沿用现有规则。
- 上次模式在成功开始预约或直接专注时持久化，设置取消不保存；预约后来取消不撤回该选择。国策视图另按本机用户保存，首次简洁，不同步、不包含画布平移缩放。
- 云操作保持明确整份覆盖；不新增逐记录协调。只读检查与执行分离，未确认前不能改变本地业务数据。检查可以记录本机检查/提醒元数据，但不得以检查为名导入记录。新快照使用云版本；旧数据保留稳定变化标记。时间排序仅供参考。
- 冷启动及前台检查须在认证与可访问状态确认后进行，前台5分钟节流；网络恢复和业务编辑不独立触发快照传输。忽略只作用当前云版本，按钮只称“忽略”；关闭不等于忽略。首见版本提示，自己上传及已下载版本已处理。
- 未结束流程期间只显示非阻断提示；结束后才允许自动选择提示，期间被忽略或版本变化应按最新状态处理，不能弹过期提示。主动上传可用，下载仍被禁止。
- 新提醒不得削弱覆盖前本地指纹/云版本复核、事务替换、验证失败目的端保留、用户隔离和生命周期限制。本地变更警告必须真实反映可确认的修改，不声称已实现逐记录差异预览。
- 同步卡片正常仅显示上次成功同步时间，不附方向；无记录显示“尚未同步”；处理中/失败/待处理优先。该时间按本机用户持久化，与云上传时间分开，检查或失败不更新它。方向和后果在弹层内保持明确。
- Android使用底部弹窗、Windows使用居中限宽对话框，支持系统返回、Escape、可见键盘焦点及大字号。来源补充Android品牌/型号、Windows厂商/机型及可辨识设备名；未知明确标注，不收集序列号，不伪造旧元数据。具体存储扩展与平台接口在实施时确定，不预先指定未经验证的新API。

## Testing Decisions

以下测试边界已获用户确认；#64已按这些边界完成取证，其余票的适用场景仍待执行。

1. 主边界：真实AppShell/页面＋真实本地仓储和Drift，替换外部认证、云端与设备读取。沿用看板集成、专注设置/恢复、手动云同步App级测试先例，从点击、键盘操作、可见内容、记录与持久状态验证行为；不测试私有变量、控件嵌套或实现调用顺序。
2. 下层补充只覆盖主边界难以稳定制造的风险：描述升级/旧快照兼容、版本和本地指纹过期、事务回滚、跨用户隔离。沿用任务仓储、快照仓储及旧云转换测试，不重复每层相同断言。
3. 时间、生命周期和平台能力复用现有可注入时钟、仓储工厂、云remote及偏好存储；必要时仅在App组合入口增加小型可替换时钟/设备元数据/偏好失败来源。新提醒协调行为从App边界观察，不因测试拆出多套UI专用接口。
4. Android 15验证触摸、Windows 11验证鼠标及常规键盘操作，两端各验窄窗口/大字号、弹层返回、流程恢复。国策偏好必须先记录修复前真实进程结束重启的现象，再在修复后保留数据执行同样操作；widget重建和热重载不是冷重启证据。
5. 隔离Supabase项目进行Android↔Windows真实往返，验证描述/型号/版本兼容、只读检查不写本地业务、拒绝/忽略/重启、并发预览过期、权限/RLS和失败无部分替换。设备测试替身结果须与真实服务结果分开记录。
6. 版本提醒覆盖冷启动/前台节流、离线/失败、首见/自己上传/已下载、相同/新版本、忽略与仅关闭、用户切换、正在预约/专注/暂停和结束后延迟提示。比较本地业务内容前后；允许仅设备提醒元数据变化。
7. 各纵向ticket承担自身自动化、两端适用设备证据及相关云边界验证。Dart变更按项目规则format、analyze与相关test，跨模块改动完整test；无须先建横向测试框架ticket或末尾单独QA票。

## Out of Scope

- 本阶段业务代码修改、迁移部署、实现、构建或设备操作；这些属于后续实施任务。
- 删除或改名普通/精锐领域链、按难度自动分配、分类迁移历史、任务移动/嵌套、自建链。
- 自动上传/下载、逐记录协调、改变活动流程结算、以忽略掩盖覆盖丢弃后果。
- 跨设备同步视图偏好、保存画布位置、跨启动目标折叠记忆。
- 原型示例数据、演示按钮、演示时长范围、模拟暂停/交接/结束规则。
- 应用软件版本更新功能、设备序列号采集、清除用户数据以便测试。
